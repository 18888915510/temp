目的：为跨渠道跟进 P1 确定邮件取数接口和默认思考档。依据本目录 CODEX-P1.md、P1-DESIGN.md；本轮不开发功能。

## 工作目录与授权边界

- 评测工作目录仅限 `%USERPROFILE%\followup-eval`（仓库 https://github.com/18888915510/temp）。本任务授权在该目录拉取、运行现有评测、生成本地结果、提交并推送安全汇总到该仓库。
- 允许只读定位当前 Hub 使用的 welink-cli 或既有 welink-ro 包装及其命令解析入口；只访问定位这些入口所需的路径，不扫描其他业务目录。只读邮件接口探测使用现有登录态。
- 不改 Hub 正在运行的目录、源码、设置和数据目录，不安装、不升级、不重启、不登录、不预置信任，不放宽只读白名单。不要输出凭据、配置秘密或个人账号标识。
- 不发消息，不调用 welink-cli 写命令，不修改邮件状态。若 mail get 默认会标记已读，只能选择本来已读的一封或使用已证实的只读参数；不能保证时停该项并报告。
- 不修改任何评测 .js/.cmd、提示词、cases.json、holdout*.json 或标准答案；不删既有日志。仅安全结果允许提交；真实材料永不提交。

## 1. 拉取及运行耗时实验

1. 记录运行前 HEAD、git status。运行 `git pull --ff-only`，应包含基线 `ad491e35e9c6c50fc68b4bc1b585b97b4887cd8e` 及本任务单；冲突或有不明本地源码改动则停下报告，不自动修复。记录实际基线完整 SHA 及脚本/题目的运行前哈希。
2. 完整读取 `run-latency.cmd`，运行一次。7 步全部串行，单次调用超时 600 秒，总计 13 次模型调用：flash 默认 H11/H13 两轮；flash low H11 两轮；GLM-5.2-WX-Auto 默认 H11 两轮；flash low H11～H15 一轮。每步自动调用 upload.cmd。
3. 不用截断输出的管道。预计约 25 分钟，允许约 60 分钟运行预算；预算后停止新增调用并报告已完成项，不悄悄重复。遇登录/信任交互、权限或网络放行需求停该受阻项并报告；不得自动确认信任或改设置。失败按失败记录，不能为了分数重跑；若外部执行被中断，仅补未执行的剩余步骤，同样参数并每步上传，不重跑已完成步骤。
4. 上传前先在源端核对各份 report.md、summary.json 精确字节数、内容仅为数字/编造编号等安全汇总；不把未审查结果留给 `git add results`。可以在脚本调用 upload.cmd 前通过本地监控核查；无法保证检查在自动上传前完成时，暂停自动入口，按其中相同的 7 步命令依次执行，逐步检查后运行 upload.cmd，并明确报告此执行方式偏差。禁止修改脚本绕过检查。
5. 逐一核实 7 次上传对应的提交和安全文件，用 `git ls-remote origin refs/heads/main` 核实最终远端完整 SHA；不能只依据“已上传”文字。记录运行后哈希，确认脚本/题目未变，提交范围只有本轮 results 文件。

- 保留 180 秒验收线；600 秒只为观察，不表示放宽验收。
- 旧 HANDOFF-latency.md 中“两次无 JSON 已证实 taskkill 掐断、只能说明模型超过 300 秒”不作为事实。本次已知证据只是：Q-1110-07 第 2 轮两个输出含 CLI 信任提示；没有独立 stdout/stderr/退出码/定时器记录，终止机制和请求是否发出未知。

- 失败检查只在公司本机做，回传错误类别和脱敏通用提示；不得回传原始 prompt/output。区分信任提示、网络错误、模型输出失败、疑似超时，无法确认就写未知。

## 2. 只读探测邮件接口

此项可在耗时实验完成后执行，限 15 分钟；查不到或需要登录/改配置立即报告已有结果，不无限搜索。

1. 找到 Hub 实际使用的 welink-cli 或既有 welink-ro 包装（只读检查解析入口），记录 CLI 版本和入口种类；本机路径若含真实用户名，回执用 `%USERPROFILE%` 等替代。不要仅用 PATH 上任意一个版本冒充 Hub 版本。
2. 获取以下完整帮助输出：`mail list --help`、`mail get --help`、`mail folders --help`、`search person --help`、`contact detail --help`。每项独立记录退出状态；不支持就按原样报告，不猜参数。安全帮助可保存至本工作目录 results/p1-env-<时间>.md，附版本与命令；不得带真实数据或私有路径值。
3. 根据 help 的真实语法，仅执行一次少量（最近几封）mail list 和一次 mail get。使用只读限制，不输出原始 stdout 到回执、共享日志或仓库。只生成 JSON 字段名和层级结构，所有标量值替换为 `<string>`、`<number>`、`<boolean>`、`<null>`，数组只保留结构代表项；如果对象键本身是邮箱/姓名/ID，也替换为类型占位。未知字段保留结构，不返回内容。
4. 重点逐项回答：能否列出已读邮件；时间范围、发件人筛选、分页语法；mail get 是否包含收件人、抄送、全文、附件名、邮件组成员；search person 是否支持邮箱查 WeLink 账号/显示名；contact detail 的输入标识和可用字段。区分帮助声明支持、实际返回字段、未实测。不需要额外查人员身份，不实际展开邮件组。
5. 如帮助说明不足，不凭空推断；说明待确认参数和缺口。所有真实内容仅在本机内存处理，不另存原始邮件。

## 3. 回传格式与大小限制

先结论，按上面两项回复。耗时用表列全 13 次结果；接口用帮助文档和类型结构说明（回执可用“字段路径 / 类型”表，避免中转过滤长代码块）。附把握程度、未读到部分、失败/补跑明细。通常只需这一次实验，不自行增加轮次。

文件回传前先核对源文件精确字节数与修改时间。单文件达到或超过 20,000,000 字节、或大小未知时，不回传原文件，也不通过压缩、编码、分页、分片或多轮消息回传完整内容。请在源端分析，只回结论、统计和必要的小片段；摘要或摘录每份最多 64,000 UTF-8 字节，标明不是完整文件，并列出跳过文件的路径、大小和原因。不要把超限文件作为附件、自动回执或其他下载产物发回。

即便小于上限，任何真实消息内容、群名、人名、邮件地址、账号密钥、原始快照、prompt/output、local-only 或完整运行日志都不得回传。只将审核后的数字报告、通用命令帮助及全部值已类型化的结构报告提交到 results/；每份列出路径、精确字节数、mtime、提交 SHA。提交前检查暂存范围；不推送任何 Hub 仓库分支，不合并、不发版。
