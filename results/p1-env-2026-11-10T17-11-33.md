## 3. 实测调用（各一次，只在本机内存/临时目录处理）

| 调用 | 参数 | 退出码 | 说明 |
|---|---|---|---|
| mail list | `--folder-id inbox --max 3 --is-read 1 --offset 0` | 0 | 返回 3 封，`isRead` 全为 true |
| mail get | `--item-id <上一步首封 itemId> --body-type Text` | 0 | 取回前后 `isRead` 均为 true；未改变已读状态 |
| mail folders | 无 | 0 | 返回 10 个文件夹 |
| search person | `--text <本机设置的邮箱> --page-size 3` | 0 | 返回 1 条，`personMail` 与查询串一致 |
| contact detail | `<上一步的 welinkId>` | 0 | 返回 1 个用户 |

已读状态核对方式：同一封邮件在 `mail get` 前后 `isRead` 都是 true，且 `itemId` 一致；没有用未读邮件做实验。

## 5. 逐项回答

| 问题 | 结论 | 依据 |
|---|---|---|
| 能否列出已读邮件 | 能 | 帮助声明 `--is-read 1`；实测返回 3 封且 `isRead` 全 true |
| 时间范围筛选 | 帮助声明 `--start` / `--end`（YYYY-MM-DD）；**未实测** | 帮助 |
| 发件人筛选 | 帮助声明 `--from`；**未实测**（未确认是精确匹配还是包含匹配） | 帮助 |
| 分页 | `--max`（0–500，默认 10）+ `--offset`（默认 0）；实测 `--max 3 --offset 0` 正常 | 帮助 + 实测 |
| 主题/附件/高级查询 | 帮助声明 `--subject`、`--has-attachments`、`--query`（KQL）；未实测 | 帮助 |
| 文件夹 | `mail folders` 返回 `folderId`，可传给 `mail list --folder-id`；实测 10 个文件夹 | 实测 |
| mail get 是否含收件人 | 含，`toRecipients` 字符串数组 | 实测 |
| mail get 是否含抄送 | 含，`ccRecipients` 字符串数组 | 实测 |
| mail get 是否含全文 | 含，`body`；`--body-type Text/HTML` 可选，默认 Text | 实测 |
| mail get 是否含附件名 | 含，`attachments[].name`（另有 contentType/size/isInline/attachmentId） | 实测 |
| mail get 是否含邮件组成员 | **不含**。`toRecipients` 只给地址/显示名，没有成员展开字段；`distribution_lists` 需另找来源 | 实测结构 |
| search person 能否按邮箱查 WeLink 账号/显示名 | 能。`--text <邮箱>` 返回 `welinkId`、`chineseName`、`w3account`、`personMail`；样本 `personMail` 与查询串一致 | 实测 |
| contact detail 输入标识 | `welinkId`（可多个，位置参数）；`--source` 默认 welink-cli | 帮助 |
| contact detail 可用字段 | 姓名、邮箱、工号、部门链、主管、手机、职位等（见 4.5） | 实测 |

## 6. 待确认 / 缺口

1. `--from` 的匹配语义（精确地址、显示名、子串）未实测；P1 若要「按发件人取后续邮件」，需先确认。
2. `--start` / `--end` 是否含边界、按收件时间还是发送时间，未实测。
3. `--query` 的 KQL 支持范围未实测。
4. 邮件组能否展开：`mail get` 结构里没有成员列表；`search group` 在只读白名单内但本轮未探测，需另测。
5. `mail list` 只有 `displayTo` / `displayCc` 扁平字符串，若 P1 需要结构化收件人，必须对种子邮件走 `mail get`。
6. 未验证 `mail get` 对未读邮件是否置为已读；本轮只用已读邮件，故 P1 取数应优先选已读或先确认只读参数。
